# KB-1608: Replace manual defvar scanning with token-based extraction

## Summary

`getDefvarDefinitionIndex()` in `definition-provider.ts` was using a character-based `extractDefvarNamesFromContent()` function to scan workspace Pike files for defvar declarations. This violated the project rule against manual text scanning on Pike source. It also hardcoded type `'mixed'` for all defvar entries and matched `'defvar'` as a substring without word-boundary checks. Replaced with `bridge.tokenize()` per file via a `tokenizeFn` callback parameter, passing tokens to `extractDefvarsFromTokens()` from `defvar-scanner.ts`, which returns accurate names, types, documentation, and positions from parsed defvar arguments. The `tokenizeFn` callback is threaded through `findDefvarDefinition()`.

## Key Files Changed

- packages/pike-lsp-server/src/features/rxml/definition-provider.ts: Deleted extractDefvarNamesFromContent(). Added tokenizeFn callback param to getDefvarDefinitionIndex() and findDefvarDefinition(). Uses bridge.tokenize() per file + extractDefvarsFromTokens() for accurate type and documentation extraction.

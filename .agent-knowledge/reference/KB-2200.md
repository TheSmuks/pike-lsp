# KB-2200: Fix review feedback on PR #2200

## Summary
Reviewer identified a regression introduced by the original fix: changing `j <= nth` to `j < nth` in Rename.pike caused first-occurrence character positions to default to 0 instead of the actual position. The original `j <= nth` was correct — to find the (nth+1)th occurrence (0-indexed as nth), the loop needs to run nth+1 times. The crash was caused by `search()` receiving a start position beyond the string length, which the bounds check `if (search_start > sizeof(line_code)) break;` alone fixes. Also added explicit character position assertions in rename tests and hardened `setup_module_path()` with `parent == ""` guard and CWD fallback across 9 test files.

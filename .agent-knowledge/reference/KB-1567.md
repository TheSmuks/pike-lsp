# KB-1567: Replace regex directive parsing with symbol-based lookup

## Summary

The `handleDirectiveNavigation` function previously used four separate regex patterns and manual text slicing to extract directive arguments from `#include`, `import`, `inherit`, and `#require` lines. This was refactored to first look up the directive from `cached.symbols` (already parsed by the bridge), falling back to `bridge.extractImports()` only when symbols are unavailable. The four regex/fallback code paths were eliminated and consolidated into a single `findDirectiveSymbol` + `extractDirectiveFromBridge` pipeline with per-kind resolution functions.

## Key Files Changed

- `packages/pike-lsp-server/src/features/navigation/definition-directives.ts`: Replaced four regex-based directive parsers with symbol-based lookup. Extracted `findDirectiveSymbol`, `extractDirectiveFromBridge`, `resolveDirective`, `resolveIncludeDirective`, `resolveImportDirective`, `resolveInheritDirective`, and `resolveInheritByLine` helpers. Removed all manual text slicing fallback logic.
- `packages/pike-lsp-server/src/tests/navigation/definition-directives.test.ts`: Updated `createMockServices` extractImports mock to handle import/inherit/require directives (previously only handled #include). Added extractImports mock to the custom bridge mock in the fallback test.

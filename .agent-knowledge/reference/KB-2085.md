# KB-2085: Trigram substring index for WorkspaceIndex symbol lookup

## Summary

WorkspaceIndex had O(n) full-scan fallback for substring queries (e.g., searching "handler" matching "requestHandler"). Added a trigram (3-char substring) index alongside the existing prefix index. Each symbol name >= 3 chars generates (length-2) trigram entries mapping to the symbol name. Lookup via `collectMatchingNames` now tries prefix index first, then trigram index, only falling back to full scan when both miss (eviction edge case). The duplicate O(n) scan logic in `WorkspaceIndex.collectSearchMatches` was eliminated — it now delegates to `collectMatchingNames`. p95 lookup for 100K symbols: 0.014ms prefix, 0.012ms substring.

## Key Files Changed

- packages/pike-lsp-server/src/workspace-index-search.ts: Added SUBSTRING*INDEX*\* constants, updated LookupState with substringIndex field, updated addToLookup to populate trigrams, updated removeFromLookup to clean up trigrams, updated collectMatchingNames to use trigram index before full-scan fallback, added substringIndex optional param to searchImportableSymbols.
- packages/pike-lsp-server/src/workspace-index.ts: Added substringIndex field, static constants, wired into lookupState()/clear(), delegated collectSearchMatches to collectMatchingNames (removed duplicate O(n) scan), passed substringIndex to searchImportableSymbols call.
- packages/pike-lsp-server/src/tests/symbols/workspace-index-lookup-perf.test.ts: New test file with 13 tests covering trigram population, cleanup, substring lookup correctness, 100K-symbol performance benchmarks, mutation consistency, eviction behavior, and delegation verification.

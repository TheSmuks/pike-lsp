# KB-2088: Revert substring match in collectMatchingNames fallback

## Summary

PR #2088 review identified that `collectMatchingNames` in `workspace-index-search.ts` had a behavioral change in its full-scan fallback path: `startsWith(queryLower) || includes(queryLower)`. This made `searchImportableSymbols` (used by auto-import completion) return substring matches in the fallback path, which it did not do before. Since the trigram index already handles substring queries above the fallback, the `|| includes(queryLower)` was redundant and unintentional. Reverted to prefix-only (`startsWith`) in the fallback. Also tightened the substring query performance threshold from p95 < 500ms to p95 < 200ms (measured ~150ms), and updated the corresponding test to use prefix-matching test data.

## Key Files Changed

- packages/pike-lsp-server/src/workspace-index-search.ts: Reverted fallback in `collectMatchingNames` from `startsWith(queryLower) || includes(queryLower)` to `startsWith(queryLower)` only, preserving prefix-only behavior in the fallback path.
- packages/pike-lsp-server/src/tests/symbols/workspace-index-lookup-perf.test.ts: Updated substring query threshold from p95 < 500ms to p95 < 200ms. Updated fallback test data to use prefix-matching names since the fallback is now prefix-only.

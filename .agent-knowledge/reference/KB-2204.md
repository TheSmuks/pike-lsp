# KB-2204: Batch config-change validation to prevent scheduler flooding

## Summary

onDidChangeConfiguration was scheduling N separate background tasks (one per open document), which could occupy both scheduler workers with background work and delay interactive requests. Replaced with a single batch task that validates all documents sequentially in one scheduler slot, keeping the second worker free for interactive/typing requests.

## Key Files Changed

- packages/pike-lsp-server/src/features/diagnostics/lifecycle.ts: Replaced documents.all().forEach with single diagnosticsScheduler.schedule batch call using key 'diagnostics:config-change-batch'
- packages/pike-lsp-server/src/tests/request-scheduler-regressions.test.ts: Added regression test verifying interactive requests are not delayed during batch background validation

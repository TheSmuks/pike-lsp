# KB-2190: ENOENT handling tests mock fix

## Summary
The PR that added `fs.promises.stat()` as the first call in `loadResolutionCache` broke 4 existing tests that only mocked `readFile`. Since `stat()` runs first against the real filesystem, the `readFile` mocks were dead code — tests passed incidentally, not because they tested the intended paths. The fix adds `fs.promises.stat` mocks inside each test, with stat either throwing ENOENT (for the ENOENT test) or succeeding (for readFile error-path tests).

## Key Files Changed
- `packages/pike-lsp-server/src/tests/services/resolution-cache-persistence.test.ts`: Added `fs.promises.stat` mocks to all 4 tests in the ENOENT handling describe block; moved `originalStat` save/restore to the outer scope (shared with file-size-limits block); removed redundant local `originalStat` from the file-size-limits describe block.
